A control room for the Claude Code agents on your repos.

Seti is self-hosted. Agents work on the machine that holds your repos, each in its own sandbox, and keep going after you close the tab. The ones that need you come first, so you can steer the whole team from a phone.

Each part of Seti, in the words of the member of the team who owns it.

@pg-upgrade

What needs you comes first

Agents that wait on a permission or ask a question go to the top of the list. Answer them in a tap and the rest keep working. Restarts do not stop the work: an agent cut off mid-turn picks up on its own.

Home is a live graph of every agent in its colour, linked to its repos, the MCP servers it calls and the subagents it runs, with the merge streak and the cost per agent beside it.

EA

An assistant that knows what can wait

The EA takes voice and chat and acts through Seti's own API. What needs you reaches you at once: on a live call, as a toast or as a phone push. Routine news waits, and when you come back one brief says what needs you and what changed.

Channels feed it: signed webhooks, reminders and pollers turn any service into events that can wake an agent or the EA.

@orders

One chat for you, the EA and every agent

An @mention reaches an agent mid-turn. The EA and agents can also send one member a direct message, which only the two of them and you see. Type /btw and a question to ask an agent why it did something; the answer comes in a side chat that never interrupts the turn.

Blobs

Seti ships its own: the agent grid, side chat, file previews, Blobs, weather, Vim mode, What's new, webhook sources and themes. The Mods page shows what each one may reach. Third-party mods install with Developer mode on and run sandboxed with only the access you grant. Build one.

You

Every agent is untrusted

Agents run code on your machine, so least privilege is the normal state and new access starts off. Only you can change it. The security model covers where each secret lives.

  • SandboxedEach agent runs in bubblewrap, sees only its own folders, and reaches listed hosts only.
  • No keys insideAgents hold placeholders; a proxy adds tokens on the way out, on allowed hosts only.
  • Guards that always holdA shell guard and your deny rules hold even in Bypass, which is off by default.
  • Yours aloneThe EA and agents cannot change security settings or read secrets.
  • Closed by defaultSeti listens on loopback; every call needs a passkey, the local token or Cloudflare Access.
  • AuditedEvery action lands in an audit log kept as a hash chain that Seti verifies.

Install in one line

Seti runs on Linux with systemd, with Ubuntu 24.04 as the reference. Start as a user with sudo; the installer asks before each step that needs it.

Install on Linux Tap to select 
$ curl -fsSL https://raw.githubusercontent.com/rickaym/seti/main/scripts/install.sh | bash -s -- --with-redis --with-ea

Leave out --with-redis and --with-ea for the smallest install. The EA's chat needs an OpenAI key; voice also needs Deepgram and ElevenLabs keys.

  1. Open a new shell, then sign in to Claude Code (claude, then /login) and to GitHub (gh auth login).
  2. Open http://seti.localhost:3006. From another machine, forward the port with ssh -L 3006:127.0.0.1:3006 <host>.
  3. Sign in with the token that cat ~/.seti/credentials/local-token-user prints.
  4. Add a repo in Settings, Repos, then start an agent.
